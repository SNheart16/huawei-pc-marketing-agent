## 清单填写

唯一清单为同目录 `manifest.json`，JSON顶层 `assets` 是素材数组。继续使用既有平台枚举：`公众号`、`微信朋友圈`、`小红书`；文件夹名称只是组织方式。静态服务根目录是 `ui`，因此URL以 `/assets/pregenerated/` 开头，不能写磁盘绝对路径或 `/ui/assets/`。

每项填写：

- `material_id`：唯一且稳定的素材ID，更换原文件内容时应使用新ID。
- `url`：仓库内真实文件的静态URL，只允许本目录内的PNG/JPG/WebP等已支持图片。
- `product_model`、`model_match_scope`：实际明确的型号；`exact`为清单声明的精确适配，`family`仅声明系列适配，`unconfirmed`不参与具体产品推荐。这里的适配声明不是视觉核查通过。
- `platform`、`theme`：适用平台与主题，不将“海报”当成新增平台。
- `contains_text`：是否自带文字；为true时直接展示原图，不叠加标题或旧文字层。
- `source_type`：固定为 `pre_generated`；`source_note`如实说明团队提供、来源和待确认限制，不能默认官方。
- `rights_status`：当前为 `unconfirmed`；`visual_check_status`：当前为 `unknown`，没有视觉识别不得改成通过。
- `text_content`：人工登记的图中可见营销文字，供现有文本核查使用；不是OCR或完整像素核查，不能证明未登记文字不存在，也不自动取得任何evidence ID。

一个平台可选择2–4张；不足2张时提示并使用实际已有数量，文案功能继续可用。预览、单图下载与整组导出必须使用同一已选ID及顺序。更换图片或文字后重新核查，不能沿用旧核查结论。

图片始终需要核实外观、完整图中文字、精确型号适用性和使用授权。程序会保留 `unknown` 及审核限制，固定文件不等于可以直接发布。
