# 复赛集成演示操作手册

本手册对应独立集成分支 `codex/final-demo-integration`。地图、长期记忆、账号系统均不在本轮范围；所有任务与策略编号从当前服务响应取得，示例中的文字不是可复用任务快照。

## 启动

需要 Python 3.11 或更新版本。根 HTTP 服务、A 客户端、预生成素材读取与 SQLite 成果存储使用 Python 标准库。Node.js 仅供前端离线测试及已另行准备的 ima 官方脚本使用。

在集成仓库根目录执行统一启动命令；启动器仅在当前进程设置 local 与 USE_MOCK=false，不调用模型、不加载 `.env`：

```powershell
python -X utf8 scripts/start_demo.py --port 7868
```

直接运行不自动加载 `.env`。启动进程必须继承下面的环境变量；只检查 OK/MISSING，不打印值。Windows 用户环境更新不会自动刷新已存在的终端或服务器，需在同一次启动命令的内存环境中读取所需变量，或在已继承正确配置的新终端启动。

| 名称 | 用途 |
| --- | --- |
| `LLM_API_KEY` | 当前文案/理解/策略/语义核查服务凭证 |
| `LLM_BASE_URL` | 当前兼容服务的 HTTPS 基址 |
| `LLM_MODEL` | 当前服务支持的模型 |
| `LLM_API_TYPE` | 可选，默认 `chat_completions`，也支持 `responses` |
| `KNOWLEDGE_SOURCE_MODE` | 本轮使用 `local`，由进程环境设置 |
| `LOCAL_KB_PATH` | 仓库外只读知识库副本，由使用者另行准备 |
| `USE_MOCK` | 本轮为 `false`，不得切换模拟绕过失败 |
| `SYSTEM_PROMPT_PATH` | 可选旧流程覆盖；默认仓库 `prompts/system.md` |
| `STRATEGY_LLM_TIMEOUT_SECONDS` | 策略专用，默认 120 秒 |
| `CONTENT_DATA_DIR` | 可选，B 成果/图片数据库目录，默认忽略的 `.content-data` |
| `IMAGE_API_KEY`、`IMAGE_BASE_URL`、`IMAGE_MODEL` | 本轮预生成模式不需要、不使用；服务端拒绝 `ai_reference`，图片操作不调用生图 API |

服务仅监听本机，不应直接暴露公网。`/api/health` 的 `backend=true` 只证明可导入，不证明模型和知识库可用。知识库与 ima 脚本不随仓库交付；本轮不使用地图变量与接口。

演示入口为 <http://127.0.0.1:7868/demo.html>；实际服务运行状态以本轮 [联调报告](demo-integration-report.md) 为准。旧 `/backend.html` 保留 JSON v1.0，首页既有原型与 B 演示按钮不能冒充真实链路。

最新演示服务由 Windows Python 运行在 7868 端口，并保持运行；刷新 <http://127.0.0.1:7868/demo.html> 使用本轮代码。本轮素材相关离线检查为 Python 59/59、Node 25/25。实际浏览器仅验证了三个平台的真实素材目录和图片加载、公众号 `article-02 → article-01` 的选择顺序在切换平台后保留，以及原图单张下载；这不是模型端到端验收。整组 ZIP、文案编辑保留选图及核查失效等另有离线测试，尚不能描述为真实业务成稿的浏览器验收。

此前最小连通检查返回 HTTP 401，约 972 ms；当时模型相关 User/Process 配置均存在且一致，不能据此认定凭证有效。本轮素材调整没有发起新的真实 LLM 请求，也未重试历史 401；需由服务配置持有人修正当前服务与凭证匹配，再显式重新验收。因此下面的业务输入与录屏步骤暂为待执行脚本，不是已验证成功案例。

## 页面与接口

`/demo.html` 使用服务端当前任务和策略，不从原型示例构造事实。以下为实际代码中的调用关系，界面按步骤提供按钮，不把某一步成功当作整条链路完成。

| 页面操作 | 实际接口与结果 |
| --- | --- |
| 首次输入 | `POST /api/agent/understand`，保存返回的 `task_id`、`revision` 与 `question_cards` |
| 卡片、自由补充、修改与清空 | `POST /api/agent/continue`，提交实际版本、`card_answers`、字段更新与 `clear_fields` |
| 读取冲突后的最新任务 | `GET /api/demo/tasks/{task_id}`，只读快照，不调用模型或增加版本 |
| 产品检索、候选事实核查 | `POST /api/agent/research` → `POST /api/facts/check` |
| 策略生成、用户确认、交接 | `POST /api/strategy/generate` → `POST /api/strategy/confirm` → `POST /api/strategy/handoff` |
| B 图文生成 | `POST /api/content/from-handoff`，服务端读取同进程已确认 handoff，并适配 B；前端不能自报事实已通过 |
| 等待实际成果 | `GET /api/content/jobs/{job_id}`，完成后 `GET /api/content/{asset_id}` |
| 保存手工成稿与最终核查 | `PATCH /api/content/{asset_id}` → `POST /api/content/validate`；B 适配器在同进程调用 A 原有 `/api/facts/check-final` 处理逻辑 |
| 下载审核包 | `GET /api/content/{asset_id}/export`；图片 unknown 的包仍明确标为审核草稿 |

每次采用实际响应中的任务版本；B 成果另有自己的 `version/expected_version`，不能用它替代 A 任务版本。最终结果位于 `asset.fact_check.a_result.final_check`，文字复制要求当前成稿、已确认策略、任务版本和文字核查全部有效；`can_publish=false` 仍可能允许复制核查通过的文字。图片未知不会被适配成图片已核验。

## 演示输入与步骤

以下是本轮待实测的演示输入；只有联调报告明确记录通过的步骤才属于已验证范围。

1. 首次想法：`想为 HUAWEI MateBook X Pro 酷睿 Ultra 微绒典藏版 做开学季推广，面向有移动学习和轻办公需求的大学生，发布门店朋友圈。只用证据明确支持的事实，不写价格、优惠、性能对比和个人体验。`
2. 根据真实返回的唯一问题补充目标或场景。若返回卡片，使用服务端选项选择；如只有文本追问则输入答案，不伪造卡片。
3. 补充自己的想法并修改受众：`受众改为研究生，其他需求保留。只突出一个有充分依据的卖点，文案真实克制。` 时间、门店和使用场景均为用户输入，保留 `unverified` 来源标签。
4. 查看当前有效需求，确认清空字段不从旧历史恢复。进入检索及生成前事实核查，展示 local/live=false、精确型号和可用事实，不能混入 2021 型号。
5. 生成真实主推策略，展示核心表达、内容结构、采用事实、假设与限制。用户亲自点击策略确认；未确认不得进入真实 handoff。
6. 将同一任务已确认策略交给 B，保留真实文案模型调用。图片采用 `pregenerated` 预生成素材；在公众号、朋友圈、小红书栏目中选择与当前产品匹配的图片并排序。没有匹配素材时显示待补充，不能套用另一型号照片。
7. 等待异步 job 完成后展示实际稿件、图像来源与模式。提交实际当前版本最终核查；文字 passed、整体 partial 与图片 unknown 分开展示。
8. 仅在文字核查允许时复制当前可用文字。单张下载取得预览对应的原始 PNG/JPG；整组 ZIP 按当前平台实际选择顺序打包，明确是待审核草稿，不能将下载等同可发布。

## 预生成素材的放置与操作

正式文件及清单位于 `ui/assets/pregenerated/`，维护方法见 [素材交接说明](../ui/assets/pregenerated/README.md)。清单为 `manifest.json`，URL 使用 `/assets/pregenerated/...`，不能填写本机路径或 `/ui/assets/...`。每项登记真实素材 ID、产品型号、平台、主题、自带文字、来源说明、授权与视觉核查状态；不能编造产品事实引用。

本次收到 12 张素材：公众号 3 张、朋友圈 3 张、小红书 6 张。小红书中 2 张型号尚未确认，1 张明确为 MateBook 14，均不得默认用于当前 X Pro 任务；X Pro 当前每栏有 3 张可选。系列匹配仅说明素材适配范围，不证明精确配置、图片内参数或视觉已核验。

在“选择配图／更换配图”中选择、取消选择；上移、下移改变展示及导出顺序。每个平台分别保存选择、顺序和文案草稿，切换回来继续编辑；修改文字或只重新生成文案不会重置已选图片。当前栏最多选择 4 张，建议 2–4 张，不足时如实提示，不重复补齐，也不阻断已完成文案。更换产品会重新检查素材适用性。

自带完整标题和排版的原图直接展示，不叠加旧文字层，图内文字不能编辑。图片加载失败需补充或更换素材，不能当作下载成功。单张下载与整组 ZIP 使用当前平台实际选中原图和顺序；整包下载仍遵守当前稿件的核查门槛。

`source_type=pre_generated` 不等于核验通过：本批素材授权仍待确认，视觉核查保持 `unknown`。清单中的 `text_content` 是人工登记的可见文字，不是 OCR 或完整视觉检查。修改图片、顺序或文案后必须重新提交当前成稿核查，旧结果不能沿用；图片 unknown 时不得宣称整套图文可直接发布。初次生成、重新生成、切换栏目、选择图片、下载和导出都不调用生图 API。

## 2–3 分钟讲解稿

“先用一句真实推广想法开始。这里不是固定演示成果：服务器创建本次任务，理解当前产品、受众和平台，只追问一个重点。选择卡片或自由补充后，左侧有效需求会更新。我把受众改成研究生，系统保留其他条件，并使旧策略失效。

接下来读取同型号资料。当前使用本地只读副本，页面明确显示不是实时在线核验。每条可采用事实都有证据和来源；没有依据的参数或优惠不能进入策略。真实模型据此生成主推方向，区分产品事实与场景假设。

策略需要人工点击确认。确认后的版本和有效事实进入 B 图文工作台，文案由配置的模型服务生成，图片采用团队预生成素材，按公众号、朋友圈、小红书分别选择和排序，不调用生图 API。原图自带排版时直接展示，图片内文字不可编辑；修改文案或换图会让旧核查失效。

最后对实际成稿全文做事实核查。文字可用时可以复制；图片外观和图中文字尚未视觉核验，仍是待确认。我们交付的是有来源、可追溯、可审查的营销草稿，不把接口成功或下载按钮说成整套内容已可发布。”

## 错误处理与重启

- 等待中不重复点击。模型耗时和异步 job 状态持续展示；失败时保留已保存信息并显示安全错误。
- 401 时停止后续模型调用，核对实际进程配置与服务凭证匹配，禁止自动切换 mock。
- 版本冲突/过期卡片时读取最新任务，重新展示有效问题，不重放旧选项或猜测 revision。
- blocked 时按具体不支持陈述修改并重新核查；不能只加免责声明，也不能放宽规则。
- partial 时仅展示核查允许的文字与图片待补项；图片 unknown 不显示“图片核验通过”。
- 服务重启后 A 内存任务丢失，必须重新创建；B 历史成果持久化不等于 A 当前任务仍存在。保留正在运行的服务完成一次演示；关闭后按同一启动命令重启并新建任务。

本轮只执行受影响检查：在根目录设置 `PYTHONPATH=tests` 后以包式 `unittest` 命令运行，Python 59/59 通过；相关 Node 检查 25/25 通过。离线使用替身，不产生真实 LLM 或生图请求。实际浏览器范围仅为上文明确列出的素材目录、加载、切换保序与单张下载。

前一轮集成离线基线：根目录 `py -3 -m unittest discover -s tests -p "test_*.py" -v`，66 项；后端目录 `py -3 -m unittest discover -s tests -v`，281 项；根目录 `node --test tests/test_prototype.cjs tests/test_ui.cjs tests/test_content_bridge.cjs tests/test_demo_flow.cjs`，117 项，合计 464 项通过。这是素材调整前的历史基线，本轮未重复全量运行。历史 A opt-in 脚本 `py -3 huawei-marketing-agent/scripts/strategy_http_demo.py --live --source-mode local --check-final` 会独立启动服务并实际消耗模型额度，不代表集成页面已验收；本轮 UI 流程应在报告所列的唯一持续服务执行，不额外运行该脚本重做链路。
